## Notes

- **Optimization strength:** identical node counts on every variant. The
  onnxslim-only fusions the onnxmodelzoo comparison calls out (ConvTranspose+BN,
  no-op `Dropout` removal, …) don't appear in YOLOX's graph, so neither tool has
  an edge here — both fold the same `Constant`/`Slice`/`Concat`/`Shape`
  scaffolding of the focus/reshape logic
  (`[["Constant", 40], ["Slice", 5], ["Concat", 3], ["Shape", 3]]` at opset 11).
- **Speed:** onnxsim is faster on nano but slower on tiny/s, where its
  onnxruntime-based constant folding and `check_n` equivalence check dominate;
  onnxslim's optimize step is lighter on the larger graphs. Both are sub-2s.
- **Shape:** `yolox-tiny` and `yolox-s` share the same backbone graph and differ
  only in input resolution, hence identical node counts.
