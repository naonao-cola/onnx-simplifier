# Transformer LMs on the Snapdragon 8+ Gen 1 (Hexagon V69): CPU, HTP (QNN), tinygrad HVX

Encoder-only and decoder-only language models on the Xiaomi 12S (SM8475), each run three ways:

- **CPU**: ONNX Runtime 1.26 on the phone's CPU, 4 threads, fp32 and ORT dynamic int8.
- **HTP**: the same static ONNX graphs through the QNN EP (strict, no CPU fallback, EP-context cache,
  `htp_performance_mode=burst`), fp16 or onnxsim whole-graph QDQ (`onnxsim.full_qdq`).
- **tinygrad HVX**: the matmul-heavy kernels generated by our tinygrad HVX codegen
  (`onnxsim/tinygrad`, stage 1 int / stage 2 qfloat) and run on the DSP through our own FastRPC skel.

All phone numbers are medians taken under the shared phone lock (`~/.cache/android-phone/phone-run`),
from `/data/local/tmp/codex-android-llm-tinygrad/`.

## Encoder: MiniLM-L6 (all-MiniLM-L6-v2), sequence 128

22.7M parameters (6 layers, hidden 384, 12 heads, FFN 1536). The graph includes sentence-transformers'
mean pooling and L2 normalization, so its output is the sentence embedding. Accuracy is the cosine
between the phone's embedding and fp32 torch's over 20 fixed sentences (`models.SENTENCES`).

| path | ms / inference | embedding cos vs fp32 (mean / min) | phone peak RSS |
|---|---:|---|---:|
| CPU fp32, 4 threads | 24.7 | 1.000000 / 1.000000 | 186 MB |
| CPU ORT dynamic int8, 4 threads | 11.1 | 0.965 / 0.948 | 90 MB |
| **HTP fp16** (fp32 graph, QNN runs it in fp16) | **1.94** | **0.999998 / 0.999997** | 446 MB* |
| HTP W8A16 (onnxsim QDQ, uint16 activations; LayerNorm/Softmax/GELU fp16) | 3.34 | 0.99905 / 0.99872 | 351 MB* |
| HTP W8A8 (same, uint8 activations) | 2.54 | 0.867 / 0.820 | 283 MB* |
| HTP int8 Linear only (Gemm/MatMul uint8, rest fp16) | 2.33 | 0.953 / 0.924 | 372 MB* |

\* peak RSS of the process that also compiled the EP-context cache on first use.

- **fp16 on the HTP wins outright.** It is 12.7x faster than the CPU in fp32 and 5.7x faster than
  CPU int8, and it is as accurate as fp32. At seq 128 the model is about 1.4 GMAC, which the HTP's
  fp16 path covers comfortably.
- **int8 doesn't pay here.** Every int8 variant is *slower* than fp16. The float islands that int8
  needs (LayerNorm, Softmax, GELU, the additive mask) cost more in conversions than int8 saves on a
  model this small. The variants that are accurate (W8A16) are the slowest.
- **W8A8 loses accuracy through activation outliers,** a known BERT property. The FFN outputs and
  residual stream have a few huge channels, so one uint8 scale per tensor flattens everything else.
  The same happens to ORT's dynamic int8 on the CPU (0.965).
- **The attention mask needed a fix before any quantization worked.** HF's additive mask is
  `(1 - mask) * finfo(fp32).min = -3.4e38`: that is -inf in fp16, and a range that crushes every
  score it shares a quantization scale with. `export_minilm.py` rewrites it to -1e4 (exp(-1e4) = 0,
  so the masking is identical), and `quantize_minilm.py` keeps the mask path and the score Adds it
  feeds in fp16. Before the fix, W8A16 was at cos 0.0.

## Files

| file | what |
|---|---|
| `models.py` | pinned Hub revisions + sha256 of the weights; the evaluation sentences and prompts |
| `export_minilm.py` | MiniLM-L6 -> static ONNX (int32 ids, bounded mask, pooling in-graph), fp32 references, phone inputs |
| `quantize_minilm.py` | CPU dynamic int8 and the onnxsim QDQ variants for the HTP |
| `eval_encoder.py` | embedding cosine vs fp32 (phone outputs or host ORT) |
| `llm_run.cpp` | phone runner: `enc` (encoder, timing + outputs), `dec` (prefill + greedy KV-cache decode) |
| `run_phone.sh` | build `llm_run`, push libs/models/inputs (by md5), run, pull outputs |

## Reproduce

Each heavy step under `systemd-run --user --wait --collect --pipe -p MemoryMax=12G -p MemorySwapMax=0`;
every phone step under `~/.cache/android-phone/phone-run`. `W=~/.cache/llm-work`, and the onnxsim
checkout on `PYTHONPATH`.

```
python export_minilm.py --work $W
python quantize_minilm.py --work $W
ORT_THREADS=4 ./run_phone.sh enc $W/enc.fp32.onnx cpu 22 $W/enc_in 20 $W/ph_enc_cpu_fp32
QNN_PERF=burst ./run_phone.sh enc $W/enc.fp32.onnx htp 22 $W/enc_in 20 $W/ph_enc_htp_fp32
python eval_encoder.py --work $W --phone $W/ph_enc_htp_fp32
```

The ORT/QNN libraries come from `../htp_exploration/qnn_shell/fetch_libs.sh` (Maven Central, not
committed).
